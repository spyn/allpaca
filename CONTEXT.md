# Allpaca Context

## MVP Scope

**In:**
- GGUF, SafeTensors, and ONNX (weight-export) model loading via `tokenizers` crate; HuggingFace Hub `org/name` download into the HF cache
- Multi-request generation up to `engine.max_active_requests` with Transient `RequestBusy` backpressure
- Continuous-batching `Engine::poll`: fair-schedules the longest-waiting runnable Request (prefill or decode) so a single driver loop can interleave Requests without hand-rolled round-robin `step`
- Chunked prompt prefill (`prefill.chunk_tokens`) so a second Request can admit or decode between chunks
- Asymmetric GPU scheduling (target on fast GPU, draft on slow GPU)
- NGram + DraftModel + MTP speculation; **DSpark** sidecar (`dspark-*.gguf` / `--speculative-providers dspark`); Token Forest (off by default) overlaps MTP draft-ahead when both are on
- DeepSeek-V4-Flash (`deepseek4`) split GGUF: MLA + hyper-connections + MXFP4 MoE (dense latent KV; CSA/HCA indexer skipped). HIP uses packed BF16 GEMV for MLA/shexp/lm_head and packed MXFP4 SwiGLU experts with a routed LRU (short prefill H2Ds active experts only, not all 256; no generic 149 GB F32 upload). CPU gemv remains the correctness path for F32 fixtures.
- VRAM + Pinned DRAM KV tiering (2-tier); optional NVMe cold KV
- Weight working set (dense pin-prefix + ring; MoE host-pool + GPU LRU + `q*` miss split)
- Windows DirectStorage file→D3D12→HIP DMA (opt-in alloc); aligned host-staged H2D fallback
- `nemotron_h_moe` hybrid schedule: Mamba-2 SSD + attention + MoE (incl. Lightning gate-less experts)
- CPU sampling with JSON mode plus `llguidance` JSON Schema / Lark constraints
- HIP backend (AMD GPU)
- Continuous-batching soft packed HIP GEMM: co-step (`batch_gemm_plans`/`batch_gemm_executes`) + real host activations × shared Target weight `gemm_nt` (`batch_gemm_hip_kernels`); greedy HIP decode cohorts skip per-request lm_head (`batch_gemm_lm_head_skipped`) and apply packed **lm_head** from fresh `output_norm` into `pending_logits` (`batch_gemm_hip_applied`); packed Q/K/V C feeds attention then WO, residual-added into the packed stream FFN consumes; packed FFN C is residual-added into that stream (`residual_add_rows`); fused `x+WO+FFN` is written into decode `last_hidden` (`batch_gemm_residual_hidden`) except when MTP needs `output_norm` for `h_nextn`
- CUDA backend scaffold (`allpaca-cuda`: discovery, `CudaWorkspace`, F32 `gemm_nt` / residual_add / rmsnorm / silu_mul / embed_gather / rope / attention / `copy_h2d_f32` for soft_x; engine opens CUDA when `gpu_backend=cuda` or auto with only CUDA GPUs; `backend=cuda` in stats when workspace open; dense TinyModel `CudaResidentModel` upload + `forward_token_cuda` for synthetic generate when device present; **Tesla K80 / sm_37** via CUDA 11.4 toolkit (`scripts/fetch-cuda-toolkit.sh`), arch detect from product name on driver 470, all-lane `__shfl_xor` attention; **CUDA-only dense GGUF** via `CudaResidentModel::upload_gguf` with **packed Q8_0 GEMV** (`stage_q8_0_*`, `gemm_nt_q8_0`, Q8 embed gather) so large weights stay 36-byte staged blocks on device (1B verified; 7B-class VRAM path); **synthetic + Mixtral-style MoE GGUF** (stacked `ffn_*_exps` F32 or **packed Q8_0** expert GEMV + topk-routed expert GEMM; router host-staged); **attention + host Mamba-2 / GDN hybrid** (`mamba2_step` / host Gated DeltaNet + CUDA rmsnorm/FFN, `RecurrentState` wired through engine); **Qwen35 GDN GGUF** F32 host-materializes projections; **Q8 GDN projections stay device-resident** (`upload_gguf` + CUDA GEMM, no host-F32 fill; **packed Q8 GEMV when n>65536**); **CUDA KV pages** (`cudaMalloc` when no HIP) + **device attention** (`attention_dev` / `attention_host_q_dev_kv`, single-page in-place, multi-page D2D pack); **packed in-layer QKV fusion** (device GEMM → RoPE → stream-ordered `write_slot_from_device` → `attention_dev`, no host Q/K/V bounce); **dense CUDA prefill M=N** (`forward_tokens_cuda` / `CudaPrefillActs`, one `gpu_forward` per chunk); **MoE chunked prefill** (device attn M=N + expert-grouped GEMM); **SSM/GDN chunked prefill** (per-token recurrent path + one `gpu_forward` per chunk); tiny host-F32 / host-dequant Q4_K / F16 llama GGUF upload/generate (7B packed quant still HIP-first))
- Vulkan backend scaffold (`allpaca-vulkan` + `allpaca-shaders`: rust-gpu SPIR-V, `ash` dispatch, `VulkanWorkspace`, same F32 TinyModel ops as CUDA; packed GGUF F16/Q8_0 GEMM stays packed (integer unpack + F32 MAC; optional glslang native-f16 GEMV when `shaderFloat16` and `glslangValidator`); Q4_K still host-dequant; engine opens Vulkan when `gpu_backend=vulkan` or auto with only Vulkan GPUs; `backend=vulkan` in stats when workspace open; dense TinyModel decode + Vulkan KV pages / device attention from resident KV + synthetic MoE/hybrid; tiny host-F32 / packed F16/Q8_0 / host-dequant Q4_K llama GGUF upload/generate (7B Q4_K / SSM/GDN/MLA still HIP-first); GDN/SSM/MLA Vulkan upload rejected (HIP-first decode; tiny DSV4 GGUF pins the MLA reject); [ADR 0005](docs/adr/0005-vulkan-rust-gpu.md))

- Kernel-ABI RPC (`allpaca-rpc-server` + coordinator `--rpc`) for HIP/CUDA layer-split across machines (same `KernelOp` / LaunchList wire ABI; `--device hip:N` / `cuda:N`; CUDA `CudaWorker`; CUDA coordinator keeps local-layer activations device-resident and host-bounces only at remote boundaries; worker KV slot writes use offset `Memcpy` D2D; packed GGUF weights via `PutTensor` + `GemmNtQuant`, no host-F32 expand; GDN and split-head blocks stay local)

- OpenAI-compatible `/v1/chat/completions` server (ChatML when vocab has `<|im_start|>` / `<|im_end|>`; those pieces are default stop tokens; no auto `<think>`)
- TOML config + CLI flags
- `tracing` logs + `/stats` JSON + Prometheus text on `/metrics` + OTLP-ish JSON pull `/v1/metrics/otlp` + optional HTTP JSON push via `telemetry.otlp_endpoint`

## Glossary

| Term | Definition |
|------|------------|
| **Engine** | The core Rust library (`allpaca-core`) that manages scheduling, memory tiers, and device orchestration. Embeddable, no network boundary. |
| **Server** | A thin binary wrapper around the Engine that exposes an OpenAI-compatible HTTP API. Chat turns use ChatML when the loaded vocab has `<|im_start|>` / `<|im_end|>`, else `role:`. Optional deployment mode. |
| **Model Format** | On-disk representation of weights, tokenizer, and metadata. Engine detects GGUF, SafeTensors, or ONNX from the weight-file extension (or a HuggingFace snapshot directory). `model.path` may be a Hub id (`org/name`, optional `@revision` / `:filename`); files download into the HuggingFace hub cache. SafeTensors follows the Hub standard: F32 / F16 / BF16, optional `model.safetensors.index.json` shards, Llama-family tensor names (`model.layers.{i}.self_attn.q_proj.weight`, …) plus GGUF-style aliases, and `config.json` + `tokenizer.json` (HuggingFace `tokenizers` JSON, not only the tiny vocab sidecar). ONNX is a weight-export importer (initializers into the CPU transformer), not a general ONNX runtime. Eventual goal is a custom tiered-memory-optimized format. |
| **Pipeline Mode** | A detected hardware profile (Asymmetric, Symmetric, MobileTiered) that sets default feature flags. Auto-detected at boot, overridable via config. Not the same as **Layer Split**. |
| **Rpc Server** | Worker process (`allpaca-rpc-server`) that owns local CPU, HIP, or CUDA memory and executes batched `LaunchList` kernel RPCs. No scheduler. `PutTensor` stores a packed GGUF tensor (ggml type + dims + raw bytes); `GemmNtQuant` uses that type. Default bind is localhost; non-loopback binds require `--insecure-bind` and a HELLO `--token`. `--device cpu` / `hip:N` / `cuda:N`. |
| **Rpc Device** | A remote worker registered in `DeviceInventory` as `rpc[host:port]` after HELLO. Treated as an extra device for layer assignment, distinct from local HIP ordinals. |
| **Layer Split** | Contiguous transformer layer ranges assigned to local target + Rpc Devices by advertised memory or `--tensor-split`. Activations host-bounce at owner boundaries. Consecutive placed layers on one worker are one `RunSpan`. A remote layer is placed only for dense attention + FFN the worker can GEMM (packed GGUF or host F32). GDN and split-head blocks stay local, which breaks the span. With no RPC workers and several local GPUs, GGUF layers are placed by bytes: each GPU takes one contiguous range, the target GPU first, sized against measured free VRAM minus a reserve, the target's lm_head, the draft model (on the second GPU), and a KV share per attention layer. On Windows the planner also caps free VRAM by the PDH adapter counter `Dedicated Usage` (`allpaca_hip_local_headroom`), which includes the desktop's share: `hipMemGetInfo` does not see other processes, and WDDM silently demotes over-budget allocations to shared system RAM. The peer GPU receives layer weights only (no embed, `output_norm`, or lm_head) in its own HIP workspace, so a draft model on that GPU does not share decode buffers with the target's layers. Per-request GDN / Mamba-2 device state lives on whichever workspace ran the layer; clone, rewind, and clear reach both. A local split runs multi-token chunks as one M=N forward that hands rows between GPUs; only RPC-remote spans walk tokens one at a time. Not tensor-parallel. Decode stays local when the plan names remote owners but nothing was uploaded. |
| **Feature Flag** | An independent, composable behavior (e.g., asymmetric drafting, DRAM tiering). Pipeline modes are shorthand for common feature flag combinations, not monolithic profiles. |
| **Control Plane** | Rust code that owns all scheduling, memory bookkeeping, token forest construction, and constraint logic. Memory-safe, runs on CPU. |
| **Kernel ABI** | A flat C interface (`extern "C"`) exposing GPU/CPU compute primitives. C++/HIP/CUDA implements the kernels; Rust calls them. No logic in kernels beyond numerics. |
| **Draft Provider** | A pluggable source of speculative token candidates. MVP includes NGramProvider (CPU trie), DraftModelProvider (secondary GPU model), MTP/NextN from the target GGUF, and **DSpark** (DeepSeek-V4-Flash sidecar `dspark-*.gguf`: Markov head now; full DFlash stack later). Missing DSpark sidecar is Degraded, not Fatal. Token Forest (tree) speculation is a Feature Flag (`speculative.tree.enabled` / `features.tree_speculation`), off by default. When enabled, packed verify runs one target eval with an ancestry attention mask; on HIP the mask is uploaded and applied on the target GPU (`tree_gpu_verifies`). Linear draft verify packs the proposed span in one Target Model forward (`linear_packed_verifies`) and rewinds rejected KV `filled`; it is used when the tree flag is off. GDN hybrids pack too: while a request's GDN state is cloned, each HIP workspace journals the step inputs (pre-conv qkv, alpha, beta), and a partial accept restores the clone and replays only the recurrent kernels over the accepted rows instead of a second forward. Mamba-2 slots or host GDN state fall back to one target forward per drafted token. The clone's snapshot slots stay allocated between verifies and are freed when the Request ends. A rejected verify defers its correction token instead of forwarding it alone: the next step drafts after it (`propose_after`, correction forced first) and verifies `[correction, drafts..]` as one packed span (`deferred_corrections_packed`), falling back to a lone forward when no draft follows. While that Target forward runs, the Draft Model proposes the next span from the full draft (`draft_ahead_hits` when the next step reuses it). An MTP draft-ahead needs the verify rows' hidden states, so it starts once they are sampled and only when the whole span was accepted; after a reject it does no work. A partial accept discards that speculative span and `propose_on` rewinds draft KV to the accepted prefix, then queues a correct next span so the following step can still overlap. MTP prompt prefill is batched: one target forward returns every row's hidden state, and the NextN block processes each token with the previous row's hidden. NextN steps that only extend draft KV (processing accepted tokens, the last draft step) skip the vocab projection (`draft_logits_skipped`). Adaptive draft depth (`speculative.adaptive`) keeps decayed acceptance counts per draft position and moves depth by one only after four verifies in a row ask for it. It grows while the next draft would still be reached in at least 33% of spans, and shrinks once the last one is reached in under 25%. |
| **Target Model** | The authoritative model that verifies draft tokens. Runs on the fastest available GPU. |
| **Draft Model** | A smaller/faster model that proposes candidate tokens for speculative decoding. Weights and draft KV stay resident on the secondary GPU (slow device) when two HIP GPUs exist; CPU fallback on 1 GPU / `cpu_only`. Draft HIP GEMM uses the same packed-dtype dispatch as the Target Model (`ResidentModel::gemm_nt`: F16/Q8/Q4_K/F32). Draft DenseKv keeps the accepted prefix: `propose_on` truncates to the shared token prefix and forwards only the suffix (plus a last-token logits refresh), instead of replaying the full context every step. Only draft token ids (and short logits) cross to the target path — never full weights or KV. Path comes from `--draft-model` / `model.draft_path` / `ALLPACA_DRAFT_GGUF` (env fills `draft_path` at `Engine::new` when unset). Gated HIP tests discover a local small GGUF under `ALLPACA_DRAFT_GGUF`, repo `models/Llama-3.2-*-Instruct-*.gguf` (same-family, preferred over Qwen; 1B Q8 then 1B F16 then 3B Q8 then 3B F16), or HF cache dirs (Llama-3.2-1B/3B if present; `models--ggml-org--Qwen2.5-Coder-0.5B-Q8_0-GGUF` including hash blobs without a `.gguf` suffix). Missing draft is Degraded; a tiny written draft GGUF is enough to wire the Engine path. |
| **KV Tier** | A memory region where KV cache pages can reside. MVP supports two tiers: VRAM (hot) and Pinned DRAM (warm). NVMe cold tier is post-MVP. Target pages are `hipMalloc` on the fast GPU. Draft DenseKv is `hipMalloc` on the slow GPU when two HIP devices exist (`draft_kv_bytes_on_device`, counted in `kv_bytes_on_device`); host Vecs on 1 GPU / `cpu_only`. |
| **KV Page** | A fixed-size block of KV cache data that can migrate between tiers. Unit of residency tracking and prefetch. |
| **Weight Working Set** | The subset of model weights currently in VRAM or a pinned DRAM ring. Distinct from KV Tiers. When the checkpoint does not fit, host (or NVMe) is source of truth and GPU residency only changes speed. Dense layers that are walked every token use a pinned prefix plus a ring (not LRU). Routed experts use a GPU LRU of complete `(layer, expert)` slots; residual misses split between PCIe fill and in-place CPU execution by measured `q* ≈ m B_P / B_H`. See `docs/OPPORTUNITY_DESIGN.md` §8. |
| **Expert Slot** | One complete `(layer, expert)` tensor group. Unit of MoE admit/evict. Not a KV Page. |
| **Tune profile** | Named bundle chosen in `allpaca-server --tune` (Max resident, Balanced, Long context, layer band, router group, or a sidecar catalog profile). Decides which routed experts are pin-preferred and how GPU expert cache vs KV is split. |
| **Keep-set** | The `(layer, expert)` ids reserved in the GPU expert LRU at load. Pin-prefer: they are never LRU victims; every expert stays routable via host/`q*`. Not Flash Spark prune (unselected experts remain valid). Saved under `[tunes."<model spec>"]` and overlaid onto `weights.cache_bytes` when that model loads. |
| **Group** | One selectable row in the tune TUI: a catalog topic (when `allpaca-keepset.json` / `coverage.json` exists), a router group (`expert_group_count` > 1), or a layer band (early / mid / late). |
| **Auxiliary Accelerator** | Dropped from scope (no Coral/NPU backends). |
| **Constraint Mask** | A bitset of allowed tokens produced by the CPU grammar engine, applied to GPU logits before sampling. Enables structured output. |
| **Structured Output** | Constrained generation (JSON, schemas, grammars). `json_mode` uses a hardcoded JSON value grammar; `json_schema` / Lark `grammar` use `llguidance`. |
| **WebUI** | Operator HTML/JS surface served by the Server at `/`. Login uses a shared password (cookie); API clients use the same secret as Bearer. Not a second control plane. |

| **Request** | A generation task with its own KV cache (`KvHandle` / KV Pages) and decode state. Multiple Requests can be active up to `engine.max_active_requests` (compiled default 1). A saturated scheduler returns Transient `RequestBusy` backpressure. Prompt prefill runs in chunks of `prefill.chunk_tokens` (compiled default 512); `begin_request` admits and processes one chunk, then `step` / `poll` continues (`StepResult::Prefill`, `prefill_chunks`) so a second Request can admit or decode between chunks. `Engine::poll` picks the longest-waiting runnable Request (wait since last progress; ties round-robin) so one driver loop can interleave prefill and decode without calling `step` on each handle in turn. On HIP a chunk of N>1 tokens is one forward with M=N GEMM (hipBLASLt when N>8 on F32; tiled Q8 when N>8 on Q8_0; tiled F16 when N>8 on packed F16). MoE and hybrid SSM/GDN checkpoints use that same one-forward-per-chunk path: attention is M=N with the decode Q/K `q_out` / `n_heads` layout (including partial NeoX RoPE). SSM/GDN walk token rows. MoE groups tokens that share an expert (`M` = group size; shared expert `M = n_tok`). On HIP, IMRoPE and gated `[Q|gate]` attention run per row inside that one forward (Qwen3.5/3.8 hybrids batch); CUDA and Vulkan keep them per-token. A `[Q|gate]` projection is only recognised when n_heads * head_dim > dim, so smaller ones stay per-token. Decode of one Request is M=1; with `engine.batch_decode` (default on), a `poll` tick that finds two or more Requests in decode (no grammar, JSON mode, vision, or speculation other than n-gram) runs each Request's step up to its final forward (its sampled token, or its n-gram verify span) and then one HIP forward over all their rows, at most 8 so every row matches a solo run bit for bit, before finishing the verifies (`TinyModel::forward_batch`, per-Request RoPE/KV/attention/GDN state), so weights and remote expert calls are paid once per tick. Ticks are serialized (`poll`, and `begin_request`'s first prefill chunk); a driver thread's foreign events go back to the front of that Request's queue. |
| **GPU Backend** | Real HIP kernels (GEMM, attention, RoPE, RMSNorm, SiLU, residual add, embed gather, Q8_0 dequant, Q4_K / TQ1_0 / TQ2_0 fused GEMV, F16 GEMV, hipMalloc, H2D/D2H/P2P copy) behind `--features hip` when ROCm is present. Weights are uploaded once to the target GPU (draft weights to the second GPU); decode GEMM uses device weight pointers (`weight_h2d_bytes` grows at load only). F32 lm_head GEMV (~128k vocab) uses four columns per warp with float4 loads. Decode Q8 GEMV uses eight columns per warp and 16 warps per block, with 36-byte column-major Q8 blocks and the A row staged in shared memory so columns do not re-read it from VRAM. An integer A×Q8 GEMV (quantize A tiles, int32 MAC, ggml vec_dot_q8-style) exists as `gemm_nt_q8_0_intdot` but is not the decode default: on Groq 8B Q8_0 it did not beat float A × Q8 (memory-bound on weight loads). A 32+scale split / wider Q8 load pass did not beat that 36-byte kernel either, so decode stays on the 36-byte layout. GGUF Q4_K / Q4_K_S / Q4_K_M super-blocks (256 elems, 144 bytes) dequantize on CPU for load and tiny generate; large Q4_K GEMM weights stay packed on device and use a fused HIP GEMV (`gemm_nt_q4_k`) that does not change the Q8_0 decode default. Small Q4_K tensors dequant to F32 at load. A `token_embd` with no HIP gather kernel (K-quants, IQ4, TQ, legacy quants) stays packed in host RAM, and each gather dequantizes one row on the CPU and H2Ds it. A tied lm_head keeps the packed table on device in GEMV layout. Large TQ1_0 / TQ2_0 GEMM weights stay packed and use fused HIP GEMV (`gemm_nt_tq1_0` / `gemm_nt_tq2_0`); small TQ tensors and `token_embd` dequant to F32 at load (same 65536 threshold as Q4_K). Large Q3_K (110-byte) / Q4_K / Q5_K (176-byte) / Q6_K (210-byte) weights stay packed and use a fused GEMV on int8 activations (llama.cpp mmvq style). Each GEMV first quantizes A to int8 with one f32 scale per 32 values (per-device scratch, locked from quantize through GEMV enqueue). Then 8 lanes own one output column, each lane takes 32 weights of every 256-weight super-block, and signed dot4s accumulate in int32 with the scales applied once per row. Up to 8 A rows share each weight load (M>8 prefill re-reads B ceil(M/8) times). Every M runs this path, so a speculative verify row reproduces the decode (M=1) result bit for bit. Q8_0 GEMV keeps 1–16 rows on its GEMV kernels, and its 8-weight dot uses explicitly rounded `__fmul_rn`/`__fmaf_rn` so the 1-row and multi-row kernels agree bit for bit. With free FMA contraction they differed in the last bit, and on Qwen3.8-27B greedy MTP output drifted from plain greedy after ~25 tokens. Greedy speculative output now matches plain greedy exactly at every draft depth. 1–4 rows cost about the same as one. Misaligned Q4_K–Q6_K weights fall back to the f32-A warp kernel. The Gated DeltaNet state update (`allpaca_gated_delta_step`) normalizes q/k in place with one warp per head, then updates the state with one warp per state row (each lane holds head_k / 32 columns, shuffle reductions), and spreads a head's rows over several blocks. A block-per-head kernel that walked the rows with block-wide reductions cost ~140 µs per token per layer on the 27B. Large IQ4_NL / IQ4_XS / Q2_K / Q4_0 / Q4_1 / Q5_0 / Q5_1 GEMM weights, and Q3_K ones whose rows are not whole super-blocks (Unsloth UD mixes, MTP sidecars), re-pack to staged Q8_0 at load (~1.1 B/elem, Q8 GEMV) instead of a 4 B/elem F32 expand; small ones still materialize to F32. Small GGUF F16 tensors (n≤65536, except `token_embd`) materialize to F32 at load. Large F16 GEMM weights, `output.weight`, and `token_embd` stay packed on device (`gemm_nt_f16` / `embed_gather_f16`; decode GEMV M≤8, eight columns per warp; tiled M>8). Tied models reuse the embed pointer for lm_head. Q8_1 GEMM weights still materialize to F32. Decode fuses residual+RMSNorm and Q/K RoPE into one launch each; decode RMSNorm is a single-block reduction. Prefill RMSNorm of N token rows is one launch (`allpaca_rmsnorm_rows`, one block per row). Prefill Q/K RoPE of N tokens is one launch (`allpaca_rope_qk_rows`; position is `start_pos + token`). Prefill writes packed K/V into HIP pages as one D2D copy per page run (not per token). Prefill embed gather of N tokens is one launch (`allpaca_embed_gather_rows` / `allpaca_embed_gather_q8_0_rows` / `allpaca_embed_gather_f16_rows`; token ids H2D once per chunk). Linear speculative verify of a draft span is one Target Model forward (`linear_packed_verifies`; lm_head M=N, then KV `filled` rewind of the rejected suffix). The next Draft Model span is proposed on the other HIP workspace at the same time (`draft_ahead_hits`). Small Q8_0 tensors (norms, n≤65536) dequant to F32 at load so decode does not stage them per token. A gated 7B/8B Llama GGUF keeps Q8_0 tensors quantized on device. Embeddings stay 36-byte linear blocks (F32 scale + aligned qs) for gather. GEMM weights are the same 36-byte column-major blocks, staged at load via n,k-aware `stage_q8_0_gemv`. F32 GEMM with M>8 uses hipBLASLt when the ROCm SDK links and Tensile heuristic returns an algo (column-major NT mapping inside `kernels.cpp`; rocBLAS still fallback on miss). Decode GEMV (M≤8) stays on custom kernels: hipBLASLt matched rocBLAS in losing on skinny lm_head (~378 ms vs ~0.5 ms custom). Q8 decode (M≤8) stays on the 36-byte GEMV; Q8 prefill (M>8) uses a tiled custom GEMM that dequants B tiles into shared memory so weight blocks are reused across A rows. There is no rocBLAS/hipBLASLt Q8 path. Prompt prefill on HIP runs each `prefill.chunk_tokens` chunk as one forward with M=N GEMM (hipBLASLt when N>8 on F32; tiled Q8 when N>8 on Q8_0; tiled F16 when N>8 on packed F16); decode stays per-token (`forward_token` / M=1 custom GEMV + Q8 GEMV + F16 GEMV). Host Q8 match tests still pass packed 34-byte GGUF bytes into the public API. Sequential target and draft decode keep hidden state in `hipMalloc` across layers; attention reads resident device KV in-place (a single target HIP page is used without a D2D pack; draft DenseKv; no D2H gather / H2D QKV). Decode/prefill attention is a warp-per-head online-softmax kernel with coalesced (float4) KV reads, not a 3-pass one-thread-per-head loop. `Engine::generate` reports `backend = "hip"`, `gpu_forwards`, `weight_bytes_on_device`, `kv_bytes_on_device`, `draft_kv_bytes_on_device`, `elementwise_gpu_ops`, `residual_gpu_ops`, `activation_h2d_bytes`, and `activation_d2h_bytes`. Decode activation H2D stays flat; D2H is logits-only for CPU sampling (one async pinned D2H per token, waited before the next sample; draft logits/tokens may host-stage to the target). Unconstrained `step` does not clone the vocab each token. Without the feature, without an SDK, or with 0 devices / `cpu_only`, the CPU fallback is used. CUDA scaffold (`allpaca-cuda` / `--features cuda`) is the F32 TinyModel subset (KV pages + device attention, tiny F32/Q4_K/F16 host-materialize); without a driver/GPU `device_count()` is 0. 7B packed-quant and SSM/GDN/MLA stay HIP. Vulkan rust-gpu scaffold (`allpaca-vulkan` / `--features vulkan`) matches that CUDA scaffold on SPIR-V; `device_count()` is 0 without shaders or a device. |
| **CPU Fallback** | A slow but functional kernel implementation using AVX2 intrinsics. Required for every operation so the engine runs without GPU. |
| **Tokenizer** | Converts text ↔ tokens. Uses HuggingFace `tokenizers` crate. Vocab comes from GGUF metadata or a SafeTensors/ONNX sidecar: either a tiny `{tokens, bos_id, eos_id}` JSON or a real HuggingFace `tokenizer.json` (BPE/WordLevel) plus optional `tokenizer_config.json` / `generation_config.json`. GGUF `tokenizer.ggml.model = gpt2` (Llama-3) encodes with BPE plus a ByteLevel pre-tokenizer/decoder (`add_prefix_space = false`) so spaces become `Ġ` pieces before merges; WordLevel+Whitespace is only the non-gpt2 fallback. Decode maps GPT-2 `Ġ` (U+0120) and SentencePiece `▁` (U+2581) to spaces, and `<0xHH>` byte tokens to bytes. HuggingFace `tokenizer.json` decode uses the crate decoder. |
| **Telemetry** | Internal metrics (TTFT, ITL, acceptance rate, `draft_ahead_hits`, page migrations, HIP decode profile buckets `q8_gemm_us` / `attention_us` / `lm_head_us` / `other_gpu_us` / `host_us`; HIP event-times one decode forward in 16, since per-kernel events on every token cost ~25 ms/token on a 64-layer model) stored in memory, exposed via `/stats` JSON, Prometheus text on `/metrics` (`allpaca_` prefixed), and OTLP-ish JSON on `GET /v1/metrics/otlp` (`Metrics::export_otlp_json`). When `telemetry.otlp_endpoint` is set, the server periodically POSTs that same JSON (`Content-Type: application/json`; appends `/v1/metrics` if the URL has no path). On HIP, `host_us` is the ITL remainder after GPU kernel events so the profile sum tracks token spacing. Uses `tracing` crate for structured logs. No OpenTelemetry SDK crate. |
| **Multimodal** | Vision/audio encoder support. Placement API + `PatchVisionEncoder` (SafeTensors `patch_proj` / CLIP aliases `visual.proj` + optional `blocks.{i}.*` or `visual.transformer.resblocks.{i}.*` ViT-lite via `vision_n_blocks`; `vision_n_blocks=0` auto-counts resblocks). CLIP checkpoint stem: `visual.conv1`, `class_embedding`, `positional_embedding`, `ln_pre`. When `vision_device` matches a HIP workspace, encoder weights upload once via `DeviceWeights` (`vision_weight_bytes_on_device`); patch linear and ViT block linears prefer HIP `gemm_nt_dev_b`, ViT self-attn prefers `HipWorkspace::attention` (device online-softmax; CPU attn fallback), and mean/var LayerNorm prefers `allpaca_layernorm_rows` (ln1/ln2 + `ln_pre`; CPU fallback; not RMSNorm). Soft-token H2D stage is separate (`vision_bytes_on_device`). Soft-prompt inject into prefill; draft suppressed when vision shares draft GPU. Server accepts OpenAI `content` parts with local/`data:`/http(s) `image_url` (AVIF via `ffmpeg`). Full OpenAI CLIP numeric parity on 9060 XT still deferred. A `.gguf` `vision_path` loads a llama.cpp mmproj with the `qwen3vl_merger` projector (Qwen3.5 / Qwen3.8 vision) as `Qwen3VlVision`; its CPU encoder matches `llama-mtmd-debug` to ~1e-3. Images resize as llama.cpp's Qwen-VL preprocessor does (aspect kept, sides multiples of 32, 8..`vision_max_tokens` tokens, default 1024). They encode on the HIP GPU with the most free memory: weights (F16 on the host) upload for the call and are freed after, so the encoder never holds VRAM outside the layer plan. The Server puts the encoder's marker (`<|vision_start|><|image_pad|><|vision_end|>`) where each image part sits. The Engine expands each `<|image_pad|>` into the image's `cols x rows` soft tokens, and gives them M-RoPE positions `(base, base + row, base + column)` while later tokens rotate at their KV position minus the saved span (`MropeLayout`, `VisionSeq`). The HIP batched prefill writes image rows over the placeholder embeddings, so an image prompt prefills in one forward. |
| **Transfer Path** | The mechanism for moving tensors between devices. At boot the engine tries `hipDeviceEnablePeerAccess` both ways (best-effort; gfx906 / kernels without `CONFIG_PCI_P2PDMA` often fail with `invalidDevice` even when copies work), then treats a successful `hipMemcpyPeer` as capable. It benchmarks that peer-copy against host staging (GPU→DRAM→GPU). `P2p` is chosen only when the copy succeeded **and** measured P2P is not slower than host staging by more than 10% (`P2P_MAX_SLOWER_FRACTION`). Host staging is the fallback when the copy fails or is slower. Never assume P2P is faster. Formal `hipDeviceCanAccessPeer` is not required. A custom kernel with `CONFIG_PCI_P2PDMA=y` (optional `intel_iommu=on iommu=pt`) is what KFD needs for `p2p_enabled=true`; see README “Dual-GPU P2P”. Speculative generate does **not** require P2P: target stays on the fast GPU, draft stays on the slow GPU, and only token-scale payloads move (`host_staging_bytes` / `draft_tokens_copied`; `weight_bytes_migrated` stays 0). |
| **Configuration** | Engine settings loaded from TOML file, overridable by CLI flags. Compiled defaults for unspecified values. No env vars or runtime API in MVP. Example: `allpaca.example.toml`. |

## Error Classes

| Class | Behavior | Examples |
|-------|----------|----------|
| **Fatal** | Return error to caller, cannot continue | Model load failure, OOM, corrupt GGUF/SafeTensors/ONNX, unsupported dtype/op, invalid UTF-8 |
| **Degraded** | Disable feature, continue slower | Draft GPU OOM → disable speculation; P2P fails → use host staging |
| **Transient** | Retry with backpressure | Page migration contention, kernel timeout |

## Sampling

Sampling (temperature, top-k, top-p, grammar masking, RNG) happens on **CPU**. On HIP, decode hidden state stays device-resident for the whole sequential target forward; logits are copied once per token from GPU to a vocab-sized pinned buffer (async, then waited before the next sample). GPU sampling is a post-MVP optimization.
